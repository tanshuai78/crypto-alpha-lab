## 1. 目标、事实与决策价值

唯一问题：能否在有限成本内，为新的 Stage 1.3 研究恢复有依据的历史候选范围，并用决策前的数据计算入池资格？本轮不构建正式币池，不检验 Alpha，也不是恢复旧 R10 的历史准入资格。

起草时工作区基线：`9712c5580682062416497191250453b267b97040`，干净。该值记录本稿观察来源，不要求未来执行 HEAD 永远等于此值；执行前须另记实际基线，相关事实发生变化时报告差异，不静默沿用。

已核对的复用边界：

- [Stage 0 报告](../reviews/2026-06-07-cross-sectional-factor-lab-stage0-data-coverage-review_CN.md) 中 `108` 是现货 `56` 加永续 `52`，不是已确认的现货回测币数。
- [旧审计入口](../../scripts/audit_factor_lab_data_coverage.py) 从当前活跃交易对发现范围，不能直接重跑并宣称历史全集已恢复。
- [已有滚动筛选](../../src/research/cross_sectional_factor_lab/factors.py) 可参考其“仅用此前完整日期”的思路，但不能修复历史候选全集遗漏；旧 `2,000 万 USDT` 门槛不是本轮结论。
- [旧资产过滤器](../../src/research/cross_sectional_factor_lab/universe.py) 的 `W/S` 前缀规则不能作为可靠资产分类，不能直接照搬；本轮只记录适配缺口，不修代码。

较小替代是只做当前五币的限定诊断；本轮调查用于判断是否有理由承担更广币池的身份、退市和数据核验成本，而非默认扩到全市场。旧 R10、Factor Lab、H1、D2 的契约、状态和权限均不改变。

## 4. 执行步骤与检查点

### A. 基线与历史范围路径

先核对用户批准的本文件 SHA-256，保存实际 HEAD、`git status --porcelain=v1 --untracked-files=all`、未暂存和暂存 patch 作为前快照，不清理已有改动。记录开始时间；身份不匹配停止。

用本地资料及允许的公开来源，判断候选目录能否包含期内上市、已退出和更名资产。记录目录范围、分页是否完整、缺口及依赖，保存足以复核的来源响应；不要求两小时内逐币补齐全历史。当前 exchangeInfo 仅作当前身份参考，归档目录仅作候选发现，均不单独证明过去持续可交易。

检查点：能列明历史候选发现路径及其已知局限。若只能获得当前名单、目录不可定位或范围无法界定，停止行情下载，直接交付不足结论；不新建公告爬虫补史。

### B. 锁定最多五个样本身份

在读取 K 线 ZIP 前，保存已取得的候选元数据快照及样本表，按下列规则锁定。只看产品身份、生命周期和来源，不查看未来收益。

| 槽位 | 选择规则 |
| --- | --- |
| 期初已有资产 | `BTCUSDT`；仍须核对本轮身份来源，不因熟悉而免检 |
| 期内新上市 | 已取得官方资料中，研究区间内开始交易的普通现货 USDT 对，按交易对代码 ASCII 顺序取首个 |
| 期内退出 | 已取得官方资料中，研究区间内停止该现货对交易的记录，按交易对代码 ASCII 顺序取首个；不把仅移除保证金或合约下架当成现货退出 |
| 更名/迁移 | 已取得官方资料中，与研究区间相交的更名/迁移案例，按旧交易对代码 ASCII 顺序取首个；新旧映射只核对元数据，不自动拼接价格 |
| 名称误筛反例 | `SOLUSDT`，核对普通资产身份及旧 `S` 前缀过滤风险，不据此选择未来策略标的 |

同代码多条来源以来源 URL ASCII 顺序稳定排序；重复交易对不追加名额。某类没有找到、身份错误或资料不足，保留空槽/失败原因；锁定后不因缺数据、校验失败或调查不方便而换币。这里的样本不是概率抽样，不能用其成功比例估计全市场覆盖率。

### C. 有限归档内容核验

每个已锁定样本仅选一个代表交易对（更名案例选旧代码）。在现有身份资料所支持的交易区间与候选研究区间交集内，固定最早相交的 UTC 月份；若该月尚未结束，事前固定改取交集内首个完整 UTC 日的 `1d` 日包。先记录确切 ZIP/CHECKSUM URL 再请求；交易区间无法支持选择日期则标记未知，不猜日期。上述选择不是下载失败后的替换：不得因请求失败改币、改月或改格式补采；按官方发布时间尚未发布的对象记 `not_yet_published`，不当作历史缺口。月份包可能含区间外日期，仅用于结构核验及此前窗口演示，仍须披露范围。

在预算内取得 ZIP 与 CHECKSUM 后，核对校验文本中的目标文件名与下载文件一致，再对实际 ZIP 字节验证摘要；不匹配或无法取得校验文本不得记为完整性通过。用标准库直接读取 ZIP 内 CSV，不执行其中内容、不做 `extractall`。仅核对记录结构、时间单位、日期顺序/重复/缺失、记录区间及 `quote asset volume` 是否可读取；价格列不用于计算或选样。报告有效日数及非完整月份，不前向填充，不把无记录日自动当成零交易。

如样本内具有连续完整 30 个 UTC 日，固定以这段最早连续窗口之后首个 UTC 日零点为演示边界，仅使用此前这些日记录计算成交额中位数，并独立核对日期集合和排序中位数；边界可落在月包末日之后，不假定该边界时刻仍可交易。不足则标记未验证。这只是复用旧流动性统计的可计算性示例，不冻结未来 30 日窗口，不应用 `2,000 万` 门槛，也不证明实际盘口深度、容量或决策时点交易状态。

区分证据等级：HEAD 支持对象存在不等于 ZIP 内容验证；CHECKSUM 可取得不等于 ZIP 匹配；403/405/超时是未知而非不存在；首末归档日期不等于正式上市/下架时刻。日度样本验证不代表 `15m` 特征/结果窗口覆盖、历史实时延迟或完整 PIT 已验证。

### D. 报告与前后不变性

停止网络与内容读取后整理下述交付。复核实际 HEAD、status、工作区/index patch 与前快照一致；记录全部命令实际退出码、请求结果和上限使用量，不把 skip、失败或推断算作通过。意外工作区变化时停止并报告，不自行恢复；未完成的项保留未知。

## 5. 最小交付与下一步路由

唯一人工报告 `report_CN.md`，含三张表：

1. **来源能力表：** 来源 URL/本地路径、取得时间、响应存档和完整 SHA-256、可证明事项、不能证明事项、目录/分页范围。元数据候选数、已支持/未知数量分列；分母不完整时不报全市场覆盖率。抓取时间不冒充历史发布时间，记录已知版本/PIT 局限及已有研究暴露。
2. **样本核验表：** 锁定规则及顺序、市场/交易对身份、生命周期证据、对象定位/校验文本/实际摘要/内容检查分别的结果、原始证据位置、缺失与失败原因。先锁表与实际核验结果都保留。
3. **复用与完整成本表：** 哪些既有函数/字段可参考、哪些不能直接复用，历史名单/退出/分类/数据缺口的剩余工作量；执行实测时间及编写、评审、复核另列，不确定估算标注区间。说明是否需要大量人工补史或新平台，而非只报最后一次下载耗时。

报告必须区分已验证事实、推断、未知和建议。只允许提出以下路由，不自行启动后续任务：

- `propose_research_design`：历史发现与有限内容核验有真实证据，尚存局限可界定、预计全量成本可控；最多支持提议正式研究 Design，不代表正式币池或策略通过。
- `bounded_diagnostic_only`：只能支持明确受限的样本范围，须说明选择偏差；不能把删去退市/缺失后的样本包装为完整 PIT 范围。
- `pause_due_to_data_or_cost`：关键范围无法界定、身份/数据问题不可在预算内处理，或必须大幅补史/建设平台。资源暂停和材料不足不是 Alpha 证伪。

不设“五个至少成功几个”的门槛，不以更多币数作为成功标准。不生成具有机器准入或授权作用的正式币池产物，后续消费者不得直接把本报告当作可交易名单。

## 6. 停止条件与审核边界
