## 3. A / C 辩论后的保留与纠正

| 议题 | 保留的经验 | 不成立或尚未证实的说法 |
| --- | --- | --- |
| 立项价值 | 问“即使为正，会改变什么决策，值不值得这些成本”；边界写全、审计通过不代替价值判断 | 不能因负结果倒推所有探索都不该做；正结果也不必直接授权交易才有价值 |
| 代理忠实度 | X 未直接表达“同等卖压下跌不动”；简化后应降级问题与声明，M0 的线性控制不能保证压力真正可比 | s1/s2 仍在模型中，并非完全丢失压力信息；5% 原为描述切点，没有证据认定先定 5% 后为凑样本改为 0 |
| 模型与目标 | 满秩不等于统计充分；必要控制、有效样本和评价目标应一起考虑；收益均值预测与下行尾部收窄不是同一问题 | 不能确定过拟合是唯一原因；负的增量交互系数不证明反弹总体效应为负或随后必然二次下杀 |
| 数据机制 | 成交数据不能直接确认盘口吸收或参与者身份，旧数据前推仍只是开发探索 | 没有证据把波动主要归于空投抛售，也不能宣称这批数据的全部信息已经耗尽 |
| 工程成本 | 物理代码共 4,723 行（生产 2,789、测试 1,934）；环境、历史接入、校验、评审和维护都应计入投入 | 未证实“85% 都是治理胶水”或以后必然重复数千行；数值分组/PIT/计权也是研究正确性的一部分，不能为缩行删除 |
| 测试与归因 | 负向测试应证明目标拒绝路径，不能只看非零退出；已修复的前置缺陷不能用来解释最终负结果 | 不要求所有测试匹配完整内部错误字符串；资源停止不等于已查明唯一经济原因 |

A 对代理简化、模型承载力和事前价值判断的批评起初不够突出；C 的具体诊断补强了这些问题，但部分动机与经济因果解释超出了证据。设计与审核者共同批准了成本结构，不能只追责实现者。最终复盘按证据取舍，不按观点属于谁来取舍。

## 4. 后续如何应用：执行现有规则，不另建流程

以下是本案例对既有要求的应用提示，不新增表单、审批、固定样本量/代码行数或每轮必问清单：

- **研究冻结前看用途与对应关系。** 在现有讨论或 Design 说明结果会改变的决策，以及机制、可观测量、候选、指标和声明是否对应。正结果最多支持继续调查时，也要说明可行的后续路径；若仍值得一次廉价诊断，明确其独立学习价值，不能只列局限就默认放行。沿用 [L2 §14.1/§15](../../.agent/rules/L2_Alpha_Research_Methodology.md#141-lightweight-research-direction-screening)。
- **准备阶段看完整负担。** 核查实际导入与复用边界，把隔离、历史契约、测试/审核和维护成本算进去。必要控制或安全检查使实验不合算时，可以暂停；不削弱基准、伪造旧哈希或自动另建平台。沿用 [L1 §2.8](../../.agent/rules/L1_Engineering_Process.md#2-core-engineering--verification-discipline)。
- **测试与收尾看证据。** 拒绝测试确认目标原因；结果按冻结口径报告，区分事实、合理风险和未知归因，不把开发前推当独立确认，也不通过事后改窗/删样本挽救结论。沿用 [L1 Rule 15](../../.agent/rules/L1_Engineering_Process.md#rule-15-legacy-l1-rule-11-test--fixture-provenance-integrity) 和 [L2 §5](../../.agent/rules/L2_Alpha_Research_Methodology.md#5-pre-registration-and-anti-hindsight)。

本次不修改规则、workflow 或 skill：现有条款已覆盖主要要求。以后只有发现明确冲突或无法覆盖的缺口，才另议最小定向修订，不因一次问题就追加规则。复盘不因代码行数回溯重开已验收任务，也不豁免真实的新缺陷。
