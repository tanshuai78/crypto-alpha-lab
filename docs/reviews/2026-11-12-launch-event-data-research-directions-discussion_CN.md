## 1. 一页结论

**现有数据仍有机制研究价值，但尚未找到被遗漏的“暴涨密码”。更值得追问的是：成交压力怎样转化成价格变化，以及什么市场条件让这种关系失效。**

- OI 和基差不能简单判为“完全无用”，已有局部改善线索，但尚无稳健、可交易的 Alpha 证据。
- 目前主要检验固定窗口、有限特征与终点收益；这不等于已经检验完成交路径、尾部风险、市场条件或跨币种影响。
- D2“上新公告对既有同行币的溢出”已完成两批有限元数据预审及一次 APRO/BOB 条件复核，现按用户决定暂停，不继续滚动扩样或启动行情研究。保留“上新事件对其他市场/资产的影响”这一研究母题；A/B/C/D1 等仍只是候选，没有自动获批或成为下一项目。
- 旧上新事件已经被反复观察，只能作为开发集；更多成交记录不等于更多独立事件。
- 不因为已经投入数据和工程成本，就必须从这批数据中提炼出某个策略。信息不足或投入不值得时，可以暂停。

## 3. 四个待讨论议题

### A. 成交压力与价格响应

**问题：同样的主动卖出压力，为什么有的币持续下跌，有的却越来越跌不动？这种差异是否在价格本身之外提供后续信息？**

此前的主动买入占比主要衡量一个窗口内的买卖构成。这里关注的是压力与价格变化的时间关系，例如：

- 卖出压力持续时，价格是否继续创新低，还是下行响应逐渐减弱。
- 压力减弱后，价格是反弹还是继续下滑。
- 买入成交很多时，价格能否持续推进，还是推进困难。

经济假设是：急于成交者可能造成短暂价格压力，另一方承担库存和逆向选择风险。该假设不证明真实参与者身份，也不预设“卖不动必涨”或“买不动必跌”。

现有 `aggTrades` 字段包含时间、价格、数量和主动方向，原则上支持成交层面的描述。具体原始序列覆盖、缺口和消费资格仍需另行核实；不能把“有这类字段”写成“分析已经可运行”。

**关键边界：**成交数据不包含完整挂单、撤单和队列过程。可以称为成交压力与响应，不能直接确认盘口吸收、大户承接或完整订单流失衡。也不能仅发现同期价格与成交相关，就称为对未来有预测力。

理论参考：[Cont、Kukanov、Stoikov 的价格影响研究](https://arxiv.org/abs/1011.6402)。该文使用股票订单簿事件，支持考虑流动性供需与价格影响的思路，不直接证明新币数据上有可交易收益。

### B. 实际成交价、Mark 与 Index 的分离

**问题：冲高或急跌时，是实际成交价暂时偏离参考价格，还是指数本身也在持续变化？**

旧研究的基差固定为 `Mark / Index - 1`。它没有增量，不等于以下关系已被检验完：

```text
实际成交价 / Index - 1
实际成交价 / Mark - 1
```

Mark 是计算参考价，不是可成交报价。比较三种价格的偏离与变化过程，可能帮助区分不同的价格发现状态；但这些变量存在机械关联，不能默认是独立的新信息。

现有成交记录及部分合约的 Mark/Index K 线原则上可作初步比较，但须核实身份、时点、粒度与共同覆盖。没有指数的样本不填零，也不与有指数样本混为同一检验。

**关键边界：**成交价偏离可能只是买卖价差、陈旧参考或短暂噪声；不代表能按两边报价成交，更不代表无风险套利。需判断它是否比已有价格和基差基准多提供信息，而不是换个公式重复解释。

参考：[Binance 对 Last Price 与 Mark Price 的说明](https://www.binance.com/en/support/faq/detail/360033525271)。

### C. OI 积累与成交换手的区别

**问题：相同的 OI 增长率，在不同成交活跃程度下，是否代表不同的未平仓规模积累状态？**

讨论中的一个候选描述量是：

```text
同窗 OI 数量增量 / 同窗成交数量
```

只有单位一致、窗口可对齐且分母有效时，这个量才有可解释性。它可能补充单纯 OI 百分比增长，但尚未计算或验证，不作为已确定特征。

**关键边界：**它不是新增空头占比、开仓交易占比或资金净流入比例。OI 对应多空双方，不能识别谁在追空、谁在承接。当前真实 OI 信息截止时间及可得性仍未验证；若沿用情景假设，结果仍是 `historical_scenario_only`，不得升级为已验证 PIT。

参考：[CME 对 Open Interest 的定义](https://www.cmegroup.com/market-data/volume-open-interest/about.html)。

### D. 上新改变市场条件，以及对关联币的影响

#### D1. 新币自身的市场结构变化

**问题：同属 standard 的事件，是否具有不同的供给、对冲与价格发现条件？这些差异能否解释结果不稳定？**

值得核实的背景包括：此前其他交易所是否已有现货或永续、现货是否同时上线、充值是否开放、是否伴随空投到账或解锁，以及当时大盘是否剧烈波动。

这些是待核实的分类维度，不是已确认的样本差异，也不意味着全部都应加入模型。优先考虑能明确改变经济机制、且能低成本取得历史证据的条件。

**关键边界：**部分信息不在现有行情表中，需补充可追溯的历史来源。不能用今天的流通量、交易所覆盖或充值状态回填过去，也不能按已知收益挑选分类。若需要昂贵的新数据管道，可以暂缓。

#### D2. 上新公告对既有同行币的溢出（当前暂停）

**候选主问题：新币官方上新公告发布后，事前按业务关系确定的同行老币组合，是否出现超出正常市场表现的正向收益响应？**

区别于预测新币自身涨跌，D2 把上新作为外部事件，把已有交易历史的同行币作为观察对象。候选经济假设是注意力扩散或同行重新定价；原有持仓者、追逐关注度的交易者与流动性提供者可能面对不同需求和风险，但当前不能识别其身份或证明净补偿。

讨论中还提出了竞争解释：投资者可能卖出老币、转买新币，产生资金分流；生态上下游也可能受到影响。这些先作为替代解释或延期问题，不同时拟合全部关系。负反应、无反应和波动增加都应如实报告，不能事后把它们改称正向主假说成功。

- **关系事前确定：**优先讨论直接业务同行；竞争、生态依赖与历史价格相关性不能混成一种关系。真正的新币可能没有足够行情估计相关系数，不能按上线后谁涨得多来挑“最相关币”，也不能用今天的行业标签回填过去。
- **时间与对照：**公告不等于开盘，须核实官方发布时间并披露更早预告。共同市场因素、同行自身消息及上新前已有行业热度都可能混淆结果。若问题是整个同行组是否被带动，不能仅用该同行组自身作基准，把目标效应一并扣掉。
- **样本与结论：**一份公告对应多个关联币仍是一个事件簇；重叠事件可能进一步相关。旧事件上的新问题仍属开发探索，不能因换研究对象就声称完全未见或独立样本外；异常响应也不直接证明因果、机制或可交易收益。
- **可行性待核实：**现有上新本币日包不保证包含同行币与对照币的同步行情。应先盘点历史关系证据、交易身份和价量覆盖；D2 初步问题不必先引入 OI，但成本、可获知公告后的反应空间和执行可行性仍不能省略。

上市公告溢出并非无人研究的领域。讨论中查阅的 [上市公告溢出工作论文](https://epubl.ktu.edu/object/elaba:150713843/150713843.pdf#page=61) 与 [共同风险因子研究](https://economics.yale.edu/research/common-risk-factors-cryptocurrency) 提供相关背景，不直接证明此候选问题有 Alpha，也不支持“其他投资者都忽略了它”的判断。

## 4. 贯穿四个议题的遗漏与推断边界

- **路径与尾部：**除终点收益，还可以讨论最大不利变化、冲高回落及先涨后跌/先跌后涨的顺序。但 MAE/MFE 两个极值本身不能恢复顺序，任何未来路径指标都不得用作事前特征。风险信息有用，不等于已经发现收益策略。
- **比较基准：**新特征要回答是否超出适当的简单价格基准，而不是只解释同期价格或比零预测更好。基准和窗口须在后续研究中明确，不能看完结果再选。
- **样本与选择：**不能只研究九个已知暴涨币，必须按相同规则保留全部适用事件。旧样本上的新结果仍属开发，随机拆分或重复留一法不能抹去既往观察。
- **成本与执行：**仅有成交和 K 线不能完整恢复可成交价差、冲击、Maker 成交概率或真实滑点。历史价格响应不等于净收益，不使用示例手续费代替真实成本证据。
- **未知与失败：**数据缺口、独立机会稀疏、所检验关系缺乏增量、成本/执行不可行是不同原因，分别表述；预算用尽或数据不足不等于假设被证伪。

### 6.1 D2 元数据预审 Brief Plan（历史方案，暂停期间不执行）

以下保留首批执行前的方案边界，供追溯，不是新的待执行指令。后续限定授权与执行情况以 §6.2 所列报告为准；当时未核实的事项不得仅因预审结束就改写为已通过。

目标是判断能否在不看收益的情况下，为历史上新事件建立可信的同行关系与时间锚点，不检验 Alpha。保留首批最多 5 个 Parent、每个新币最多 3 个同行、半天预算及单份人工报告；不新建代码、机器消费链或审批流程。

**固定样本，先锁定再核验。** 候选范围仅为既有冻结分类账本中的 Binance `crypto / standard / confirmed` 永续首次上线候选，不扩展交易所或混入盘前、现货、TradFi。先按既有公告时间来源中的原记录时间（UTC）、稳定 `parent_article_id` 排序，记录来源及首批 5 个 Parent；再做当前页面和事件资格核验。即使后来发现时间错误、类别不符或资料缺失，也保留原名单、原排序时间、核验时间及原因，不重新排序、不补第六个。多 child 公告仍算一个 Parent，相关 child 的核查状态分别披露。

**排序依据的真实缺口：**[J-C 冻结 Design §4.1](../designs/2026-10-23-external-signal-shadow-lab-stage1-5j-c-launch-time-path-feasibility-design_CN.md) 记载的账本 12 列不含公告发布时间，不能直接写成“按账本已有公告时间排序”。制定本方案时尚未读取账本或确认来源，要求执行前明确可关联 Parent ID、既有且获准读取的公告时间元数据来源；后续首批报告记录采用旧 J-A 目录的 `release_date_ms` 及稳定 Parent ID 排序。如果候选集合无法形成可信排序，仍应报告“排序依据不足”并停止选样，不用当前网页更新时间、计划开盘时间或方便核实的事件替代。

**固定同行，先选定再检查行情对象。** 仅纳入公告前有可信历史证据的直接业务同行，按以下优先级选最多 3 个：关系上先明确的直接竞品、后可证明提供相同核心业务/服务对象的同行；同关系等级先同期原始项目材料、后同期可信第三方材料。同等级再按历史英文项目名及可核实的稳定资产标识字典序排列，记录排序依据。宽泛叙事、同链或共同投资人不足以单独认定直接同行；关系或资产身份无法核实则记未知，不硬凑三个。记录已发现的其他合格同行及超额未纳入原因，同时披露人工检索不保证穷尽。同行名单不依据价格、市值表现或行情覆盖选择；选中后缺数据或无对应合约，也不替换为数据齐全的同行。

**固定市场，不用现货代替永续。** 统一检查 Binance USDⓈ-M、USDT 保证金/报价永续的 1m K 线归档，BTC/ETH 对应 `BTCUSDT`、`ETHUSDT`。历史交易身份必须有来源依据，当前交易对清单不能独立证明公告当时存在。只有可信历史证据支持当时无该合约时才记 `instrument_unavailable_at_event`；无法确定则记历史身份未知，不从 ZIP 404 推断合约不存在，不改查现货、USDC、币本位或交割合约以补齐。身份已核实的对象检查公告日前一天、当天、后一天三个 UTC 日；这只是对象预审范围，不冻结正式研究窗口。若核验时间跨日改变，记录原/新时间并以核验后的公告日定位对象，但不改变 Parent 名单；日期无法核实则保留定位缺口。

**限定证据等级，原样记录请求结果。** 拟允许的联网操作仅为公开公告/历史关系资料查阅、ZIP 的 HTTP HEAD 及同名 `.CHECKSUM` 文本读取；不得 GET 市场 ZIP、解压或解析行情。报告记录 URL、检查时间、HTTP/请求结果及依据，使用以下证据标记，不创建机器 Schema 或准入状态机：

| 标记 | 本阶段含义与边界 |
| --- | --- |
| `archive_object_found` | 对正确定位对象的响应支持其存在，不证明 ZIP 内容、完整性或分钟覆盖 |
| `checksum_available` | 可取得校验文本；未下载 ZIP，未核对实际 ZIP 哈希；与对象存在标记分别记录，不是互斥状态 |
| `archive_not_found` | 在对象 URL 和历史产品身份可核实的前提下，有明确的对象不存在响应证据；仅限该对象，不推广为该合约或全部数据不存在 |
| `availability_unknown` | 403、405、超时、接口不支持、日期/身份无法确定或其他证据不足；不当作不存在 |

三天对象均可定位也不能写 `price_coverage_verified=true`，不能证明每分钟有效、时间对齐、真实交易可得性或成本可测。实际 ZIP 哈希、分钟连续性、记录内容和研究消费资格留待正式研究阶段。

**只交付五类事实，不设置成功比例门槛。** 人工报告列明：锁定名单中可核实公告时间的数量与失败原因；能事前建立同行关系的数量及依据；最常缺少的历史关系证据；同行币与 BTC/ETH 的历史身份及归档对象可定位/未知情况；进入正式研究的最大新增数据成本。记录超额同行、未完成调查和既往结果暴露，不做收益比较、相关性计算或 Alpha 判定。排序无法建立时也如实报告，不伪造五个已锁定样本。

半天到预算即交付现状，不为凑齐五个“成功事件”追加调查。多数事件无法建立可信历史关系时，可建议暂停 D2 工程，而不是补建大型历史标签库；这是资源分配判断，不是统计证伪。资料较完整也最多支持考虑正式 Design。

**权限仍分离：**读取冻结分类账本或公告时间元数据前，须核对有效版本、身份、适用准入及明确只读权限，不因采用 Brief Plan 跳过既有 J-C 或上游消费边界。方案本身不授予账本/受限源读取、联网请求或报告之外的写入权限；实际操作依当次明确允许的只读来源、限定网络操作与人工报告写入执行。不运行旧 loader、生成新 receipt、读取行情数值或启动研究，不修改既有数据、代码或已批准契约；现按 §6 暂停。

### 6.3 本轮讨论保留的认识与未立项方向

**保留研究价值，不把新意当成优势。** 新币上线可能改变交易工具、对冲条件、注意力或流动性分配，因此值得保留对其他市场/资产影响的母题；这是可检验的机制假设，不是已经观察到这些影响。市场有波动、不等于由上新造成；由上新造成、不等于能在获知后取得成本后优势。“其他人都只盯新币”及“范围外一定有机会”目前没有证据。

**不要求完美因果识别才可探索，也不跳过替代解释。** 公告前预热、共同市场变化及相关资产自身消息都可能混淆结果。未来若做有限探索，应事前固定对象、时间与基准，披露残余不确定性；扣除 BTC/ETH 后出现异常收益仍不是单独的因果证明。

**人工关系判断不等于无效。** 清楚定义、来源边界、结果不可见时的一致应用及适度独立复核，可以支持研究；固定“两次搜索”只是成本约束，不是无偏保证。代币价值捕获不同也不必然否定注意力溢出，应先说明要检验哪种关系，不以齐全度或后来涨幅替换资产。

以后可以逐项比较以下更明确的切口；它们均未立项、未冻结参数、未获数据消费或运行授权：

| 待讨论切口 | 为什么可能更明确 | 必须保留的疑问 |
| --- | --- | --- |
| 同一资产既有现货/其他场所市场，对新增永续的响应 | 资产身份通常比主观同行关系更清楚；可讨论做空、对冲与价格发现条件变化 | 须先确认上新前确有该市场；竞争、跨场所成本与延迟可能吃掉响应，不预设能套利 |
| 有事前明确权益或经济联系的其他资产 | 例如公开规则中的持有/质押资格与奖励关系，传导链比宽泛同叙事更具体 | 可能是另一类事件，不能混入原永续上线 Universe；也不能默认链上 gas 币或平台币必然受益 |
| 事前固定的既有市场篮子，观察注意力/流动性再分配 | 不在结果出现后挑出涨得最多的“关联币”；可先问波动、成交或风险条件是否改变 | K 线不能完整恢复深度、价差、撤单或净资金流；风险信息可能有用，但不自动等于收益 Alpha |

A“成交压力与价格响应”也只是另一个候选：可复用部分成交字段、少做关系标注，不等于已有优势。若以后讨论，须区别于旧主动买入占比，问其是否超出既有价格与主动成交信息提供增量；不能把 `aggTrades` 称为完整盘口吸收证据。
