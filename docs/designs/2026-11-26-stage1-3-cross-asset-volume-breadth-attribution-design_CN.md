## 3. 固定对象、广度与因果时间

### 3.1 先固定对象，不重新排队

`A=volume_spike_1h`，`B=relative_strength_vs_btc`；唯一键为 `(candidate,symbol,available_at_ms)`。Q 的 964 行用于来源对账和特殊周时间线；本轮广度分组的唯一目标集合 `J` 为原成员中 `group=joint` 的全部 155 行。保留原 `A=overlap_suppressed` 也满足放量的定义，不取 A/B 两个 admitted 队列交集，不因过滤释放 B 占用，不补入后续机会。

沿用 UTC `[2026-06-15,2026-11-23)`、四个目标币 `ETHUSDT/SOLUSDT/XRPUSDT/DOGEUSDT`，BTC 仅为原 B 参考。原 15m 网格、60s 假定数据延迟、严格晚于 available_at 的参考入场及四小时终点全部不变。Y 为原 B 行的 `10000*(exit_close_price/entry_open_price-1)`，不是新交易成交或组合收益。

### 3.2 唯一新指标

对目标事件 i，令 `t=available_at_ms`、目标币为 c，`L=one_hour_bar_count*bar_interval_ms=3600000`。对其他三个目标币 j，查看原 A 决策键 `(A,j,u)`，其中 `t-L < u <= t`；即严格排除左端、包含当时已可得的右端。核验原 15m 网格、1h 特征窗及 `u=window_end_ms+60000`，每币预期四个决策点。排除目标币自己，也不把 BTC 加入分母。

每个决策点的放量事实仅作如下判定：

| 原 A 状态及字段 | 当时放量事实 |
| --- | --- |
| `admitted` / `overlap_suppressed`，有限 `trigger_value>=3.0` | 已知触发 |
| `not_triggered` 且 `trigger_value=null` | 已知未触发 |
| 缺行、`feature_not_estimable`、`block_boundary_censored` | 未知，不能补零或重建 |
| 重复键、未知枚举、状态/值矛盾、时间错位或非有限值 | 输入无效，停止 |

`H_j(t)=1` 当该币窗口内至少有一个已知触发点；即使其他点未知，已有触发证据也足以证明“曾触发”。`H_j(t)=0` 只在四个预期点均存在且均为已知未触发时成立；其余为未知。新指标 `G_i=sum_j H_j(t)`，只有三个 H 都已知才可取 `0/1/2/3`，否则 `G_i=null`。一币重复触发只计一个币。逐点来源键/状态及触发证据必须可追溯。

这里测量的是“过去一个完整小时内曾发生放量的其他币数量”，不是四币同一瞬间触发，也不是新的小时成交量聚合。每个原触发自身仍基于此前一小时特征。L 是继承的观察尺度，不是已验证的最佳窗口；原 3 倍门槛亦无最优含义。不改成 6.83 倍、不合并成 `G>=2`、不扫描窗口或门槛。

### 3.3 可构造性先于收益

源码事实：`stage1_3_fixed_universe_diagnostic.build_event_ledger` 会在调用 detector 前检查参考结果窗口/块边界，故 `block_boundary_censored` 不能解释为“未放量”；仅查 admitted 会漏掉真实触发。新构造只读取所需的原 A 时间、状态和触发值，不用其他币后续收益、原对照均值或终局观察结果推算 H。

先对固定 155 行构造 G 并锁定来源键/组别，后联结原 Y/MAE/MFE。任一目标 G 未知，就保留全部 155 行及缺口、停止新的分组收益分析；不得删未知行后冒充全队列结果。时间线可交付，缺口是本单有效结论。解决缺口若需要重读 ZIP、重跑 detector 或改上游，按 Rule 16 停止，不扩建。

`u<=t` 是按原 60s 假定延迟重建的历史信息边界，不证明实际实时取得过该数据。该周身份、整周中位数、事后收益、未来同周对照以及“本周已是最佳周”都不能输入 G；历史归档事后发布的限制保留。
