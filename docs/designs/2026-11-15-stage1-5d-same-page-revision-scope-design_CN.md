# Stage 1.5D 正式修订仅保留同页改期 Design Delta

状态：Draft，待 Model B 独立审查及用户按 SHA-256 批准。源码事实基于 `ea4b3142364245a5429d8ea10c8ace72c1a9d5dc`。本稿不授予实施、启用或部署权限。

## 1. 目标与取舍

1.5D 保留普通合约上新、已正式发出上新文章的有界同页改期，以及原有显式新根补采协议。本 Delta 只停止主动追踪单独发布的延期、改期、取消通知，不再为它们建立正文抓取任务或产生正式修订。普通上新公告不是独立修订通知；币安另发一篇带有效上线计划的普通上新公告时，仍按原入口独立处理。

用户明确接受：如果新时间只出现在独立修订通知中，原公告不更新、也没有新的普通上新公告，可以漏采。未开盘时继续依赖 1.5F 的现有 `exchangeInfo` 就绪门禁；这不保证识别全部官方取消，也不承诺每次实际开盘都能采到。失败时不拿旧锚点或 API 时间猜测新官方计划。

## 3. 最小变更与非目标

- 移除独立修订标题主动入队；新版本生产 runner 不再调用通用跨文章修订发射路径。沿用同页重查的现有来源校验、冷却、预算、时间上限、版本首观测和 canonical v2 writer，不另起调度器、不新增模式开关。
- 恢复加载的独立修订旧工作不得进入调度、详情预算或正式发射；同页重查资格按 §3.2 在本轮重建。不按共享的 `detail_work_type` 一刀切停掉合法同页重查，不迁移、不删旧根或重写历史证据，保留普通上新及原显式恢复规则。只对新运行决策生效。
- 不新增 News 栏目订阅、列表请求、回溯或跨文章匹配；不靠标题的“延期”字样全局拦截普通上新。独立通知出现在既有列表原始响应中时，允许按原保留策略留存；不要求加请求去补详情。
- 在普通上新入口、建立详情工作或发出新事件前，窄排除主句明确宣布推迟、重新安排或取消某次合约上线的独立通知，包括带 `USDⓈ-Margined` 的 `Will Postpone the Launch of ...`、`Will Reschedule the Launch of ...`、`Will Cancel the Launch of ...`。不从单个关键词或栏目推断，也不声称识别所有未见过的句式。合法 `Will Launch ...` 新公告不因附带提及旧延期而被拦；对已发文章的同页重查不依赖当前标题仍符合普通上新句式。恢复时同时覆盖过去被误放进普通队列的这类明确独立通知，不以旧工作类型或旧分类结果绕过筛选。
- 不改 1.5F/1.5G 业务逻辑、旧正式行消费、持久化结构、事件身份、PIT、污染处理、窗口或风控。保持 `--future-launch-recovery` 的原授权、同根消费者证明及 `recovery_validation_only` 上限，不自动复活既有终态，也不为 HYPE/TRX 延长已过期窗口。
- 不实现 AIA 归因、取消传播或无锚点解析新分支。不删仍服务历史兼容或合约测试的通用工具。受影响的主要实现边界为现有 D runner 和既有入口测试，手册只需说明新范围及启用证据；具体白名单由获批后的 Plan 冻结。

保留全量独立通知能力会引入额外内容解析与关联成本，且非本轮采集目标。不再主动消费这些通知比修补 AIA 或新增双模式更小；只有以后实际观测到被排除通知造成值得追回的漏采，才另行立项，当前不做兜底。

**接受的残余成本：**当取消仅由独立通知发布、原页不改且没有其他既有停止信号时，原上新文章仍可能符合有界同页重查资格，最迟在原事件首观测起的 14 天固定期限后停止。保留既有 600 秒冷却、每轮最多安排 1 个同页重查工作及共享详情/HTTP 总预算和普通首次详情保底；这不是每 600 秒必发一次请求、也不是必然占满 14 天。实际次数随运行时长、请求结果和预算变化。不为减少这类残余请求恢复独立取消监听或延长 F 等待窗口。

### 3.1 不同文章的 F 事件及证据归属

不同文章的普通上新用既有 `event_type + source_article_id + symbol` 分别识别，并用各自的 `event_symbol_id` 追踪接纳、盘口与完成记录。新普通公告不是对旧文章的正式修订：无论旧件处于 waiting/pending、active 或 terminal，都不按同 symbol 把新时间、状态或证据写给旧件。旧件 active 时沿用既有窗口和证据归属，不抢占、不重贴标签；旧件 terminal 时不复活。新件不得因旧件的同 symbol 或终态被误判为重复，但仍受原有来源、水位、就绪、全局容量及启动时限约束；旧件 active 占用的合法容量不绕过。

短时重叠的可判定样例：旧 `S0=10:00` 到点仍非 `TRADING`；10:07 收到并持久化另一篇合格普通上新，`S1=10:10`。10:10 提供有效、新鲜 `TRADING + onboardDate=S1`，使旧件所见的 API 时间比 `S0` 晚 10 分钟，严格超过既有 60 秒容差。即使未到旧 15 分钟晚启上限，旧 pending/waiting 也应为 `pending_anchor_conflict`、无新 depth 请求；其他门禁满足时只允许新件按 `S1` 开始，检查接纳和盘口均绑定新件 ID。API 只验证就绪与冲突，不能改写任一官方锚点。

现有 F 不提供跨文章的“最新公告优先”规则。若 API 仍报告旧时间或时间差在容差内、不能区分两份计划，不保证阻断所有旧件或只启动一个观察；若已 active，也不靠新文章反向认定旧件已被取消。该类结果不得当作新计划归属已验证，不能把旧证据计入新件。API 缺失或过期继续沿用旧门禁。Plan 阶段须先核对现有 F 接线，实施中只以入口回归证明上述既有隔离；若明确时间冲突的验收场景无法成立，或要求在证据不足时也保证新件优先，按 Rule 16 停止，不能在本 Delta 下新增 F 互斥、抢占或跨文章归并。

### 3.2 恢复后的同页重查资格

先用已批准的 scheduler 恢复和来源绑定核验加载原状态。旧工作的 `source_article_id` 必须与已持久化的可信原始 `futures_contract_launch` 事件及本根正式 index 一致；对文章的每个目标 symbol，要求实际唯一 index hit，并对账 `source_root_id`、`event_id`、`stable_schedule_identity`、`source_anchor_contract_hash`、可信官方锚点与可核验的旧 `payload_sha256`。按既有契约检查原身份首观测及 `formal_row_durable_at_ms` 均不晚于本轮决定；复用既有来源/根绑定和索引冲突检查，不能用仅有的外置 snapshot 替代本根 durable 事件/索引。队列状态、标题、单独 symbol 或 `detail_work_type` 不构成资格。

上述字段是资格证明，不指定每轮逐条重扫或建立第二套索引。现有 `load_valid_formal_launch_identity_index` 可提供索引读取与冲突检查，不能单独证明与本根正式事件逐字段相符。Plan 须明确从哪条现有启动/恢复校验、canonical 事件和索引构造路径取得并复用这些证据，并补齐必要的局部对账；禁止因 loader 成功就跳过绑定检查。若无法在现有 D 路径内以有界证据核验成立，按 Rule 16 停止，不默认增加全量历史重扫、持久化结构或独立 Verifier。

过滤旧修订工作须早于同页候选去重/排序及 `select_detail_retry_attempts`。不把旧修订工作直接恢复为可请求项；对已经正式发出的合格文章，由现有同页选择路径按其最新适用官方计划和 watch 重新派发，继续遵守原固定期限、冷却、交易就绪和详情/HTTP 总预算。没有本轮合法重查上下文的旧修订工作不参与排序、预算或正文请求，也不用于发射；不能挤掉同轮合法同页工作或普通上新的保底槽。新正文仍须经原同页身份、可信度及新锚点校验后才能发射；不新增持久化字段、重置期限或把已发上新重放为普通事件。

## 5. 启用证据与权限

`REAL_FIXTURE_VERIFIED` 在收窄版本上仍表示真实覆盖已验证：使用具备来源、完整摘要及各版本可得时间依据的 HYPE/TRX 同页材料，独立对账两个正文各自的 symbol/时间、从生产 D 接线发出的正式修订及 F 应用；同批 API 只支持该次快照的产品、计划时间与交易状态。受控离线回放不是历史 VPS 观察。所需真实绑定缺失、仅有单版本 helper pass 或跨模块正向不通过时，启用继续受阻。不得伪造历史可得时间。

本次 D runner 属于 `PROTECTED_TREE_MANIFEST`；若 Plan 选择在共享上新分类器而非 D 入口守卫实现窄筛选，该 parser 也属同一受保护树，须明确白名单及调用方回归。代码验收与上线启用分开：启用前适用 Part A、真实同页 D/F 核验须绑定收窄后的实际代码 proof commit，旧热修复证明不能代用；后续配置提交继续通过现有静态、Git、消费者与运行门禁。D/F 启动或重启按既有流程另行批准，并提供与实际运行根、提交及进程匹配的 F 证明。保持只读影子模式，不重建历史根、不承诺补采上次 HYPE/TRX，也不改变旧任务结论。

路线：Model B 独立审查此 Delta → 用户按精确 SHA 批准 → 起草并审核限定 Implementation Plan → 用户授权实施及独立验收 → 真实验证和启用操作另行授权。不得自动 commit、push、SSH、部署、启停采集、恢复历史运行、paper 或 live。L2 不适用，本任务不涉及 Alpha。
