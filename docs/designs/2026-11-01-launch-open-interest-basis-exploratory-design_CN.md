# 新合约早期持仓量与基差探索 Design

**日期：** 2026-11-01

**状态：** `design_candidate` / `hypothesis_only`，待独立评审与用户批准。

**权限：** 仅授权起草本文；不授权实现、网络下载、消费受限上游、研究运行、交易、部署、SSH、commit 或 push。

## 1. 目标与已有事实

探索新合约上线早期的持仓量变化是否与之后的价格响应有关，以及这一现象是否值得在既有价格、成交额和主动买入占比之外继续研究。持仓增加既可能伴随动量，也可能伴随拥挤和反转；OI 的多空持仓双向对应，不识别多空意愿或机构身份。基差仅为补充描述，不与 OI 组合选股或事后寻找最佳阈值。

既有 [主动买入占比研究 Design](2026-10-31-launch-taker-buy-share-residual-response-exploratory-design_CN.md) 的历史样本已反复观察，本次不是独立预注册或样本外验证。六事件预审只表明所查部分日期包有 5 分钟 OI 与分钟标记价格；预审含事后选中的极端上涨事件，不代表全样本覆盖。归档时间标签不等于当时发布或接收时间；部分所查 Pre-Market 指数归档缺失也不证明所有来源均无指数。

本阶段仅产生 `exploratory` 的历史描述和下一步假设，不能证明因果、预测能力、净收益，不能作为信号或交易准入。极端走势不等于可实现利润，OI 变化不证明逼空。当前没有验证这些历史记录的实时可得性。

## 2. 范围与输入

- Universe 沿用上述研究的 J-C 分类口径：`asset_class=crypto`、`classification_status=confirmed`、`listing_regime` 为 `pre_market` 或 `standard`；以 `(parent_article_id, symbol)` 识别 child。保留全部选入事件和缺失原因，不以事后收益、OI 可用性或六事件预审结果选样。
- 事件锚点沿用 J-B 的 `T0`：按其既有契约在计划上线后确定的参考成交锚点，不推断 T0 之前绝无成交。按实际输入核对唯一键、时间和来源。公告 Parent 是主要聚类单位；同 Parent 多 child 或跨机制出现不增加独立公告数，另报 UTC 日期集中度。
- 输入候选包括 J-A/J-B 经授权的数据及分类 ledger、历史 `metrics` 的 `sum_open_interest`、`markPriceKlines/1m` 和 `indexPriceKlines/1m`。历史文件身份、下载来源、日期、覆盖及时间语义须在实施计划与运行前确认。六个临时样本仅作可用性线索，不保证剩余事件覆盖。若使用上一研究输出作机器输入，先核对其明确禁止下游机器消费的边界，未经适用授权不得消费；也不得把临时输出默认为正式数据源。
- Funding 仅作数据覆盖描述，不纳入信号；不研究订单簿、资金流身份、做空交易、执行、净 PnL 或方向择优。不改变既有上游产物和冻结契约，不因缺数据自动增建采集系统。

## 3. 固定观察口径

时间均用 UTC。主要观察点 `D=T0+15m`：相对 `T0+10m`，在使用至少早于 D 5 分钟的归档标签时，通常更有机会取得两条 T0 后、相隔 5 分钟的记录；这不是声称 15 分钟是最佳入场点，也不保证实际收到数据。

**首审后的口径修订决策：** 以下三项是对首审候选稿的研究协议调整，不是格式性修改；已在修订前向用户说明并获同意继续修订，但不构成对本 Design 的批准。最终须以用户明确批准的完整版本为准。

- 将敏感性余量由 `1m / 10m` 改为 `1m / 3m`，保留 `5m` 主场景：在固定 D 和两点均不早于 T0 的条件下，10m 余量仅在 T0 恰好对齐五分钟标签时可能形成有效对，3m 用于检查另一种可计算的时间假设。该选择基于时间网格的数学关系及六事件预审的标签和 T0 错位事实，而非比较后的收益结果；它改变敏感性覆盖及分组结果，不代表比 10m 更真实或更安全。
- 新增 `floor_5m(T0)` 补充对照：首审前已看到 IRYS 的 `16:00` 与 `16:05` 两条 OI 及其事后涨幅，故该对照明确受到已观察个案启发，**不是独立预注册或样本外验证**。它可能覆盖主口径排除的事件，但不改变主分组或其分母；只按下文规则对全部 Universe 报告，不能仅挑选上涨案例。
- 参考入场窗口由 `[D,D+1s]` 改为 `[D,D+5s]`，目的是降低无成交导致的潜在样本损失；此前未对全样本比较这两个窗口的覆盖或收益，5 秒不是实测执行能力或经过优化的参数。它可能改变入场价、实际终点及完整样本分母，故新结果不能与首审口径或既有研究结果直接视为同口径对比；未匹配仍记缺失。

**OI 主指标：** 在同 symbol 的有效记录中，取 `T0 <= L1 <= D-5m` 里标签最大的记录 `L1`，及其标签恰好早 5 分钟的记录 `L0=L1-5m`；`L0` 也须满足 `L0 >= T0`。两者的 `sum_open_interest` 均须为有效正数，`oi_change = OI(L1)/OI(L0)-1`。若缺任一记录、重复或不满足条件，标记缺失，不插值。记录两个标签、与 D 的时间差及原始值。主指标使用 `sum_open_interest` 数量而非 `sum_open_interest_value` 名义价值；实施前须确认字段单位，同一合约两点单位须一致。数量变化反映未平仓数量的净变化，不证明资金净流入、多空方向或杠杆倍数。

**时间语义：** `label` 是归档标签，`information_time` 是记录实际反映的信息截止时间，`available_time` 是当时发布并可被接收的时间；三者不得混同。为防止未来信息，须基于可核实的来源语义确定每条记录的 `information_time` 或可信上界，并保证其不晚于 D。若可证实 `information_time <= label`，则满足 `label <= D-余量` 是一种充分的信息时间条件；若信息可能晚于标签，只有存在可核实的上界且该上界不晚于 D 时才能计算。无法确认截止时间或可信上界时，停止对应 OI 领先价格比较并报告 `evidence_insufficient`；不将无依据的余量当作证明。即便信息时间满足条件，也不能由此证明 `available_time <= D`。各余量仅是未验证的实时可得性情景，须标明假设及其局限。

**敏感性：** 保持 D、标签选择及其余规则不变，分别使用 1、3、5 分钟标签余量，5 分钟为主场景。对 1m 和 3m 各自报告 Universe、OI 对及 OI/路径完整的 child 和 Parent 数、缺失原因；各机制分别对该场景完整 child 和完整 Parent 按 §4 相同口径重新计算中位数 high/low、组数与 `terminal_return` 均值差（high 减 low）。任一组为空则差值为 `null`；不要求敏感性场景重复逐 Parent 剔除。不得以结果选择主余量，且不得把覆盖不同的组间差异当作时效影响的纯因果比较。更大余量可能因窗口规则而无法组成两点，须与源文件缺失分开报告。

**开盘网格补充对照：** 对每个事件固定 `L0=floor_5m(T0)`，`L1=L0+5m`，仅当两条记录均存在、有效且 `L1 <= D-5m`，并符合上述信息时间约束时计算相同的数量变化。记录两标签、`T0-L0` 和两标签与计划上线时间的差值；报告各机制 child/Parent 覆盖及缺失，不按结果筛选案例。该对照允许标签早于 T0，仅用于探索，不混入主分组或作交易信号；不宣称 L0 是首笔成交时的初始持仓，亦不证明实时可得性。若 T0 恰好对齐网格，可与主口径重合，须注明。

**基线与基差：** 价格基线为 `[T0,D)` 第一笔与最后一笔成交的价格变化、该窗口总成交额与主动买入成交额占比；窗口结束之后的成交不得进入特征。`basis = mark_close / index_close - 1`：须通过可核验的产品/指数映射确认 mark 对应目标合约、index 对应其合法标的指数，且价格单位兼容；两种分钟线必须同一自然分钟，结束时间不晚于 `D-1m`，取满足条件的最新一对，报告 bar 时间与距 D 的年龄。映射缺失或不唯一、指数缺失或无有效正价格时基差记缺失，不用其他指数、零或 premium 代替；基差缺失不改变 OI 主分析样本资格。1 分钟余量也是未验证假设。基差和基线只作分布、覆盖及 OI 对照描述，不把差异解释为已经证明的增量预测力。

**后续价格响应：** 在 `[D,D+5s]` 内取按时间及 ID 排序的首笔作为参考价 `P0`，记录 `entry_delay_ms=entry_time-D`；未匹配则缺失。终点为 `E=entry_time+15m`，仍取 `[E-1s,E]` 内最后成交 `PE`。`terminal_return=PE/P0-1`，路径包含 entry 后至 E 的成交，计算相对 P0 的 `long_mae` / `long_mfe`。缺少参考成交或可验证路径则缺失；这些是成交价路径，不是可成交报价、止损或实际 PnL，5 秒窗口也不是实测执行能力。若当日跨 UTC 日须使用对应日期包，禁止借用其他事件数据。

## 4. 汇总与研究判断

- 在各机制内分别报告 Universe、完整与缺失的 child / Parent 数、UTC 日期、缺失原因及数据年龄。只对 OI 主指标与后续路径均完整的 child 做组间描述：使用该机制完整 child 的 OI 变化事后中位数分组，严格大于为 high，其余为 low，平局不拆；空组如实报告。该分界不是 PIT 信号或可部署规则。
- 两组都报告 `terminal_return`、`long_mae`、`long_mfe` 的均值、中位数、最小/最大值及 P25/P75（nearest-rank），并列示基线与基差的覆盖及分布。对 `(parent_article_id, listing_regime)` 内全部选入 child 都完整的组，取 child 指标中位数作为 Parent 描述值；按各机制 Parent 的 OI 变化中位数同法分组、等权汇总。跨机制同 Parent 的独立计数仍只计一次。
- 集中度检查：每个机制逐个剔除完整 Parent，重算剩余 Parent 的中位数分组及 `terminal_return` 的 high 均值减 low 均值，列出 Parent、分组数量、差值与非空范围；某组空时记 `null`。同时列出极端值和各 UTC 日期 Parent 数；不删除极端样本后只报告有利结果。
- 既有价格和成交指标仅提供描述性对照；不构造多变量筛选或训练模型来声称增量预测力。样本少、缺口大、标签时效未知或结果被单个 Parent 主导时，结论为 `evidence_insufficient` 或说明敏感性，不填零、不把缺失当负结果。观察到历史差异只支持提出未来独立事件的后续假设，不自动否定或晋级任何策略。
- 不制定未经证据支持的胜率、止损、成本或容量门槛。费用、点差、滑点、资金费率、借贷、流动性及执行容量本阶段均未建模；MAE 不是可执行止损。实盘、paper 和 shadow 策略验证均不在本研究范围；若之后考虑推进，须另行规定独立数据、成本与风险控制。

## 5. 验收与边界

1. `INV-01`：原上游、权限和研究契约不变；消费前核对适用授权、数据来源与身份，未经授权不下载或运行。研究产物不授予机器下游或交易权限。
2. `INV-02`：Universe 与缺失分母守恒，Parent 聚类、机制分组和日期集中度可复核，不根据结果改变样本或时间口径。
3. `INV-03`：特征按既定 D、标签余量和窗口计算，严格防止未来数据；每条记录保留实际标签及假设，不宣称发布时效已证实。
4. `INV-04`：OI、基差、参考成交、收益和 MAE/MFE 有可复核定义；缺失、跨日、错误记录及价格/数量单位不被静默修补。
5. `INV-05`：汇总含分布、Parent 敏感性和所有延迟场景，不将描述统计称为策略收益、预测或样本外证据。
6. `INV-06`：实施时使用独立手算样例检查 OI 两点及两者下界、信息截止上界、三种余量和开盘网格对照、自然分钟与产品映射、基差缺失不影响 OI、5 秒 entry/1 秒 endpoint 边界及延迟、路径、Parent 平局与空组；纯计算可使用合成数据，上游兼容性按现行契约检查真实权威输入。输出做基本结构和身份检查，不默认增加独立 Verifier、Recorder 或恢复状态机。

新增输出只供人工阅读及复核，写入授权的新目录，不覆盖源文件或既有输出；记录输入身份、计算版本、缺失与假设。读取失败、身份不符、顺序错误或来源语义与假设冲突时停止受影响计算并说明；来源明确缺失可作为缺口报告。是否允许联网下载、消费受限历史数据或运行研究，均须另按实际情况取得明确授权。

## 6. 后续流程与待核实事项

按现行流程提交独立 Design Review，用户明确批准后起草精简 Implementation Plan；Plan 经审查并获批准后方可实施，实际网络、历史消费和运行按适用契约另行授权。本文不改变任何既有授权，也不授权 commit、push、部署、SSH、signal、paper、live 或 execution。

Plan 必须落实 OI 归档时间与单位的证据及未知项、合法来源和覆盖、J-A/J-B 消费资格、跨日输入和可复现性；若无法确认信息截止时间或可信上界不晚于 D，停止相关 OI 领先价格比较并报告 `evidence_insufficient`，不能把假设包装为事实。历史数据无法满足时不自动转向实时采集或修改上游。
