## 2. 术语、范围与非目标

| 术语 | 本文件含义 |
|---|---|
| SSOT | Single Source of Truth，同一规则的唯一完整正文 |
| 契约 | 对外可观察行为、数据含义、权限或消费者依赖；不等于每个内部实现细节 |
| 本地修复 | 恢复已批准行为，不扩大授权，不改变冻结语义 |
| 独立核验 | 证据不与被测实现共享所要排除的错误；不必一律重新实现整个系统 |
| 简短方案 | 对话或现有任务记录中可追溯的目标、范围、禁止事项和验证方式，不要求独立文件 |
| 正式链 | 独立 Design、B review、用户批准、独立 Plan、B review、用户实施批准 |

范围仅为工程治理文档、项目自创技能和引用关系。保留 L0 资金安全及 L2 研究方法论；不新增任务风险等级、风险打分器、审批服务、Recorder 或技能管理程序。

非目标：不修改业务代码、测试代码、阈值、部署、数据、历史收据；不安装/更新/卸载外部技能；不重新判断 J-C 研究结论或完成状态；不清理全局技能目录、插件缓存或其他项目。

## 4. 新任务的最小流程与措施选择

### 4.1 何时用简短方案，何时进入正式链

新任务满足以下全部条件时可采用简短方案：目标明确、局部可逆；不改变资金安全、授权、研究冻结语义、公共契约、持久化生命周期、部署或跨模块运行流程；验证可以在现有边界内完成。单纯“文件在 src 下”不再自动决定文档数量。用户明确要求正式 Design/Plan 时仍遵从。

新增非平凡能力、重大重构或改变上述边界时进入正式链；影响不清时先调查，仍不清才问一个会改变实施路径的问题。不得仅凭“离线”降级，也不凭“交易模块”对注释修改套整套运行验证。

简短方案仍需用户明确授权其范围；明确的局部修改请求可以构成授权，咨询或要求起草不构成实施授权。重大逻辑变更仍需独立审查；局部低影响修改可由执行者给出直接验证，不强制三模型各重复一轮。不得因此降低资金执行变更的独立审查与 shadow 验证要求。

需求澄清关注需求与示例的区别、允许的副作用、完成证据和结果消费者。已能从仓库查明的事实不问用户；“参数是否举例”等 J-C 四问是示例，不是固定问卷。术语按需要在现有文档内解释，不强制 GLOSSARY/ADR/spec/ticket 文件。

通用模板精简不覆盖专用规范：研究 Design 仍满足未修改的 L2 §15，包括该节要求的明确说明或 N/A 理由；本次取消的是通用工程模板的无条件展开，不是研究证据要求。

### 4.2 机制由失败后果触发

| 实际风险或需求 | 最小充分处理 | 不得自动推导 |
|---|---|---|
| 外部调用、凭证、下单、部署 | 明确操作授权、能力隔离和对应失败行为 | Design/Plan 批准等于外部操作批准 |
| 唯一数据或共享状态可能损坏 | 禁止覆盖、备份或与后果相称的恢复方案 | 所有可重算输出都要完整恢复状态机 |
| 多写者竞争或消费者可见半成品 | 单写者约束、完成标记、原子发布或必要的锁 | 所有文件都要 flock；仅原子 rename 就证明断电持久性 |
| 要求故障后仍保留确认成功的数据 | 针对实际存储环境定义持久化与故障验证 | 所有任务默认双向 fsync |
| 输出被自动消费或支撑重要决策 | 明确结构与语义契约；选择必要的独立核验 | 文件跨进程便要复制完整生产实现 |
| 单次可重算、无并发消费者的输出 | 保护输入，清晰标记失败，拒绝将半成品当成功 | 可重算等于可以跳过计算和时间语义验证 |

措施及理由写在已有设计/任务说明中，不另建风险台账。以下是对 Rule 17 的显式、前瞻性契约变更，不是仅整理措辞：变更对象为 `docs/designs/2026-10-09-governance-cross-boundary-artifact-schema-integrity-design_CN.md` §3.2–3.3 所定义的通用义务（原文件 SHA-256：`73006481a7a390213e7912d2bc5fb04d61dde77088176d82547cf9110951e4f4`）。原文件 bytes 不修改；本方案经第 8 节生效后，才对新任务采用下表规则。

| 既有义务 | 新任务的处理 |
|---|---|
| 跨 producer/consumer、进程、生命周期或下游阶段的持久化产物必须定义并验证契约 | 保留：声明结构、数据含义、来源、失败状态、消费条件及相应 producer/consumer 检查；不能只验证哈希 |
| 仅因跨上述边界便必须建立完整不可变 profile tuple、exact-key/sealed-tree/投影和独立 verifier（不复用被验收逻辑） | 取消这一自动触发；改由下述明确条件决定验证强度，不要求低影响输出复制整套封存协议 |
| 高影响产物的独立验证及身份绑定 | 产物直接授予操作权限、控制交易/资金准入或支撑不可逆迁移时，保留原 §3.2–3.3 的 profile、结构/封存约束、独立 verifier 及审计身份绑定义务；接受逻辑不依赖被验证 producer/loader 的实现 |
| 同一既有 profile 不可静默改变语义、放宽检查 | 保留：沿用既有 profile 或已批准产物契约，即继承全部原义务；改变接受语义须按原契约审批并使用新的 profile ID/version，不能借新任务名称降级 |

上述跨边界的新研究产物，若未触发高影响或既有契约要求，可以不建立专用 verifier，但须在 Design/Plan 中说明真实消费者、结构检查、独立语义证据及未覆盖限制，经 B 和用户批准后实施。独立手算/已知答案、独立计算路径或不共享目标错误的消费者核验可承担对应证明；只让 producer 与其共用算法的 loader 相互确认不够。不得把这种验证称为已通过旧版 Rule 17 完整 profile 验证。结构检查也不能替代数值、时间或样本语义证明。

执行者不得自行改变上述分类或降低已批准检查。结果从探索参考提升为正式下游契约输入时，先审查新增消费边界并补足验证；提升为授权或资金准入依据时，必须先满足高影响要求，不能先消费后补审。既有 J-A/J-B/J-C 的 profile、verifier、source/receipt 绑定及未完成义务均不受此变更追溯影响。

### 4.3 测试、证据和完成

测试优先观察稳定行为边界；允许直接测试复杂纯函数，不为了“公开接口”增加封装。合成输入可以验证计算与故障路径，不能证明真实归档覆盖、来源真实性或真实上游兼容。声称后者时使用相应 canonical 构造器、严格 loader 或验证过的真实 bytes。

期望值来自手算、已知答案或独立规范，禁止直接调用被测算法生成正确答案。纯逻辑性质测试可作为补充，但不替代尚未证明的集成要求。负向测试应能定位失败原因；必要复合状态明确列出变异，不强求所有故障只能改一个字段。

完成要求是本次目标、范围、相关行为、接线和必要验证均有证据；不是“测试全绿 + 哈希一致”通行证。哈希绑定身份，不证明算法正确。保留真实命令与退出码；不能以 scanner GREEN 替代语义核验。

scanner、回归、Graphify 按修改影响选择时点：本次治理不更改 scanner 程序或规则；适用的 Python 变更在最终验证运行 scanner，重大边界修改可提前检查，纯文档不制造 Python 扫描任务。已声明的必需检查不省略；更新的代码会使受影响旧结果失效。Graphify 为辅助线索，不强制每 Task 更新；必要时用 source 和 rg 验证。

审查范围包含已提交、暂存、未暂存和未跟踪变更，并扣除已有基线的归属影响；不能以 HEAD 差异为空证明无实现。基线缺失时明确不确定性，禁止补造历史记录或覆盖用户文件；阻断范围应与无法证明的要求对应。

## 5. 修复路由与角色停止条件

| 情况 | 路由 | 批准边界 |
|---|---|---|
| 实现偏离已批准要求，允许路径内可修 | 本地修复并定向回归 | 不修改 Design/Plan；不把文件白名单当作任意语义修改许可 |
| 只需增加路径/任务，不改变 Design 目标、契约、权限和研究语义 | 有限 Plan 增补 | 修改前停止越界动作；增补绑定原 Plan path/SHA，B 审查受影响范围，用户明确批准；无需新 Design |
| 改变 Design 契约、权限、研究语义或生命周期 | Design 变化及关联 Plan 变化 | 保留原批准 bytes，评审并重新批准变化 |
| Finding 证据不足或与真实契约不符 | 调查、请求最小证据或有证据拒绝 | 不机械接受、不自动改代码 |

有限 Plan 增补必须检查原任务的身份依赖：Plan path/SHA、source bundle、运行授权、RUN_ID 及绑定证据。增补不把旧批准或证据自动升级为新版本；触及绑定身份时，按原任务契约重验或重授权，不覆盖旧对象、不将旧输出重新绑定到新身份。未受影响证据可在明确原身份与适用范围后保留；仅新增不在冻结 bundle 内的测试文件，不自动要求全量研究重放或新 RUN_ID。例如 J-C 若触及其冻结 source bundle，仍执行原 Gate 4.5 和新 release/RUN_ID 要求；本条不建立全项目统一运行授权协议。

沿用 `BLOCKED_IMPLEMENTATION_DEFECT / BLOCKED_SCOPE_DRIFT / BLOCKED_SPEC_DRIFT` 名称时，含义限于上述事实，不把普通修复升级为整个项目停机。缺少权限时只停止对应操作，不发明新授权文件。

A 负责需求与设计；B 负责独立文档审核；C 负责授权实施；最终独立审计不由执行者自我批准。简单任务不强制完整角色链；正式链继续保持职责分离。

必修 finding 必须指出要求、证据、可达失败或关键验证缺口和最小修复；风格偏好为 advisory。复审只覆盖 previous OPEN、直接受影响边和新引入缺陷，无新证据不重开已关闭区域。无法关闭时可以如实提交 PARTIAL/OPEN 请求决策，不能为满足“全部 CLOSED”而自证。

`complete` 只表示声明范围内实现完成，不自动批准 commit、merge、deployment、runtime 或交易。审计默认只读，在回复中交付；确需落盘时由用户或被明确授权的角色保存审计原文。审计报告若承担自动授权作用，另按真实消费边界验证；不默认建设专用 Recorder。

更新规则：先识别来源及本地差异，再按来源和版本定向更新；禁止整目录覆盖 `.agent/skills/`。未知来源标 `unverified`，不编造上游 SHA，不用最新版覆盖本地文件来“恢复原状”。本次只登记，不实施下载或恢复。

项目适配写在相应 workflow：禁止自动 commit、保留项目文档路径和批准步骤、审查当前工作区而非只看提交范围。适配先于技能调用提供；上游使用该方法不新增项目步骤。若原技能无法服从边界，暂停冲突动作并采用项目流程或请求决定，不悄悄编辑上游。未来确需深改时另行批准并使用项目 fork 名称。

## 8. 生效、兼容与失败处理

本 Design 以及其批准都不使新治理自动生效。采用一次受控维护窗口，不建设版本管理服务。未来 Implementation Plan 必须落实以下切换步骤：

1. **先保存旧权威，再开始改动。** Task 0 记录实际 Git 基线、已有 staged/unstaged/untracked 归属，保存本次适用的 AGENTS、L0/L1/L2、workflow、审核 skill/Prompt 的旧版可读 bytes 及 SHA。已提交且未变的文件可用固定 Git 对象读取；未提交旧内容单独保存，不能仅写 HEAD。保存位置及精确清单由 Plan 冻结，不覆盖既有文件。
2. **暂停并隔离任务消费。** 用户确认同一工作区其他 Agent/会话的开发与审计任务已暂停后，才修改常驻规则；窗口内仅允许本次获批迁移、定向修复和独立验收。向执行者和审计者显式提供旧权威身份及暂停边界；新会话必须先收到该上下文，不能因自动加载了候选 AGENTS 就启动普通任务。无法确认暂停或基线身份时不开始/不继续迁移，不擅自停止 VPS 服务。
3. **审查者使用独立于候选的依据。** 权限、操作纪律与独立审查方法来自保存的旧基线；目标行为来自获批的本 Design/Plan。两者共同构成验收依据，不读取新改写的审核 skill 作为自身批准权威。明确获批替换的旧条款按新规格验收，否则无法验证治理变更；未被替换的要求继续有效，尤其不能用未来简化链绕过本次正式批准。B 无仓库时上传这组精确 bytes。
4. **接受精确版本后恢复任务。** 独立验收记录候选文件清单、SHA 及相对基线变更；用户明确接受这一版本并宣布对新任务生效。接受前再次比对，若有变化则复核受影响部分，不沿用旧审查结论。恢复普通开发时使用新会话或显式重新加载已接受规则，不能混用会话残留的旧版上下文。commit 不是生效条件，也不会因此获得授权。

新任务使用生效版本；已批准任务默认继续其原 Design/Plan 的明确义务及批准时治理基线。需迁移时明确列出改变的义务，由对应 Design/Plan 变化批准，不静默采用新规则。历史编号、路径和 bytes 保留；删除旧 workflow 只消除现行入口，历史回溯用批准时 Git 版本。旧基线不可解析时停止受影响任务并请求精确证据，不把最新规则当历史原文。

删除前先区分现行入口与冻结历史引用。Plan Task 0 从当前 workspace 列出三个待退役 workflow 的实际引用者、迁移目标和未解决依赖，不能仅继承本 Design 的事实摘要。现行入口在本次白名单内同步；若发现名单外仍依赖旧文件的有效入口，暂停对应删除并申请有限范围增补，不修改所有历史文档。配套 README/checklist/pressure cases 必须同步，不能仅改 SKILL.md 首页。

若实施中断、验收失败或候选文档互相冲突，新版本不得生效，维护窗口保持暂停，只允许受控修复/复核；不继续普通开发以试探哪条规则更宽松。用户选择继续迁移，或授权按旧基线恢复本次确认所属的 diff，核对一致后解除暂停；不覆盖用户其他改动，不使用破坏性全库 reset，已批准历史对象不改写。没有新 runtime/artifact schema、磁盘协议或恢复程序需要实现；此处恢复指治理文档的一致版本恢复。

## 9. 假设、未决事项与下一步

非阻断未知：第三方文件确切来源版本、不同客户端的自动加载方式、历史调用频率。实施者登记可证实内容；来源不明保持原件不动。依赖未知来源进行更新、移除或权限放宽时，该未知转为阻断，此类动作不在本范围。

无需要在本阶段选择的新研究假设。L2 的收益分布、样本独立性、成本和策略晋级章节在本治理 Design 为 N/A：本文件不产生 alpha 或执行可行性主张，相关研究任务仍遵从未修改的 L2。
